# Existing platform inventory

Baseline: `1dd52d4`; audit date: 2026-11-06. Python/FastAPI modular monolith, PostgreSQL canonical persistence, Redis coordination; Next.js rendering/gateway remains preserved. No Android project exists at baseline. F30 operator controls also exist beyond the requested F0–F29 baseline.

## Critical boundaries

Market data → intelligence → forecasts → directional → strategy → portfolio → risk → leverage → execution → broker. Decimal financial values and UTC timestamps; immutable forecasts/outcomes. Native Spot dispatch is independently blocked; derivative execution is synthetic only. Android is never an execution engine.

## Integration gaps

Existing APIs lack native bearer sessions. Research/backtesting support GET artifacts only, with no durable submission/job scheduler API. Watchlists lack whole-list deletion. F25–F29 operational state is local/operator-only. Providers include explicit public Coinbase and SEC imports, fixture/synthetic providers, optional native Binance GET-only observation; availability is not implied by implemented adapters. No provider starts on Android launch.

## Persistence

SQLAlchemy/Alembic migrations 0001–0016 cover audit, catalogue/candles, forecasts/outcomes, Analyze, watchlists, scans, manual portfolios, intelligence, fundamentals, derivative/context observations, datasets, backtests/research/registry, PAPER journals and operator control. Spot/derivative journals have separate local SQLite boundaries. No financial state is merged across manual/PAPER/broker accounts.
